# Admin Agent Notes

- Scope: This route owns the hidden admin at [app/admin/page.tsx](app/admin/page.tsx), the Firebase-authenticated dashboard in [components/admin/AdminConsole.tsx](components/admin/AdminConsole.tsx), the bootstrap route in [app/api/admin/bootstrap/route.ts](app/api/admin/bootstrap/route.ts), and the Firebase content adapters in [lib/firebase/admin-content.ts](lib/firebase/admin-content.ts).
- Auth rule: The admin gate now uses Firebase Auth email/password accounts. UI access also requires an active Firestore document at `adminUsers/{uid}`.
- Data rule: Structured release-plan data and the booking board both live in Firestore at `adminProjects/walls-devine`. Public content docs now live at `adminProjects/walls-devine/publicContent/{docId}`, currently including `collectorHeroNote`, `bookingBannerNote`, `upcomingShows`, and `linkHub`. The `collectorHeroNote` doc now drives the public hero eyebrow, title, salutation, body copy, hero CTA labels, signoff line, and journal label, while `bookingBannerNote` drives the booking-banner eyebrow, title, description, CTA labels, and meta line. The `upcomingShows` doc powers the public upcoming-shows section and its editable show lineup. Instagram drafts and journals live in Firestore markdown docs at `adminProjects/walls-devine/markdownFiles/{collection}--{slug}`. Storage under `admin-projects/walls-devine/{collection}/{slug}.md` is legacy migration input only.
- Release sync rule: Google Calendar-ready release events can also live in `releaseTasks/{taskId}` once the calendar sync layer is enabled. Keep each task document aligned with the calendar event schema: `summary`, `description`, `start`, `end`, `gCalEventId`, and the `extendedProperties.private.firestoreId` back-reference on the Google Calendar side.
- Booking sync rule: Tour holds and confirmed routing dates live in `bookingRoutingTasks/{targetId}` when calendar sync is enabled. Mirror the booking target name, market, status, `start`, `end`, `gCalEventId`, and `syncSource`, and keep the calendar event tagged as `[TOUR HOLD]` or `[TOUR CONFIRMED]`.
- Leads rule: Public collector captures and guided-intake booking leads live in Firestore at `ecosystemLeads/{leadId}` and are read back from the admin console by authenticated editors only.
- Backlog rule: The admin console now uses a backlog-first view. Any module marked `pending` in [components/admin/AdminConsole.tsx](components/admin/AdminConsole.tsx) is intentionally hidden from the active workspace and listed in backlog instead. When recommending next admin work, start with those backlog items before proposing new surfaces.
- Bootstrap rule: Local JSON and markdown files remain only as seed data for the bootstrap route. They are not the live backend anymore.
- Rules rule: Keep [firestore.rules](firestore.rules), [storage.rules](storage.rules), and [firebase.json](firebase.json) in sync with the actual admin collection contract before deploying.
- Setup doc: Use [app/admin/firebase-setup.md](app/admin/firebase-setup.md) for the exact enablement flow, document shape, and deployment commands.
- Avoid: reintroducing local cookie auth, duplicating release-plan state outside Firestore, or creating new admin collections without documenting them here first.
